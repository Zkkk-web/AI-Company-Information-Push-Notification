# 大厂幼年体公司情报

本仓库的飞书应用机器人交付已经从“逐篇新闻列表”升级为“公司级 BD 线索”。Jev 仍只负责 A/B 级候选筛选；候选通过后，由 `trendradar.intelligence.company` 完成以下工作：

1. 从标题和 RSS 摘要提取公司、主要业务、所属方向、融资阶段、总部与团队所在地、资方、团队和触发事件；飞书展示时将相关字段合并为更紧凑的条目。
2. 字段缺失时尝试读取公开网页正文；网页失败不会阻塞当天推送。
3. 使用 `config/company_profiles.yaml` 中带公开证据链接的公司画像修正别名、错误公司名并补齐已核验字段。缺少来源 URL 的画像会被拒绝，不允许把猜测写进推送。
4. 按校正后的公司名合并同一公司的多来源报道，保留最多四个证据链接；官方资料和已核验资料优先展示。
5. 合并证据后执行 BD 成熟度门槛：排除 C 轮及以后、Pre-IPO、已上市、画像明确排除及配置中的成熟公司；阶段未知的早期线索保留。
6. 只输出报道或公司画像中有明确文字证据的内容；缺失值显示“暂未从公开报道确认”。
7. 生成飞书 `post` 可直接渲染的 Markdown，不使用 `<font>` 等卡片专属标签。

该能力只作用于 `FEISHU_OUTBOX_PATH` 对应的本机应用机器人交付，不改变原有飞书 webhook 交互卡片及其他通知渠道。

配置位于 `config/config.yaml`：

```yaml
notification:
  channels:
    feishu:
      company_intelligence: true
      fetch_article_text: true
      company_profile_catalog: "config/company_profiles.yaml"
      mature_company_exclusions:
        - Anthropic
        - DeepSeek
        - OpenAI
        - Waymo
```

环境变量 `FEISHU_COMPANY_INTELLIGENCE`、`FEISHU_FETCH_ARTICLE_TEXT` 和 `FEISHU_COMPANY_PROFILE_CATALOG` 可以覆盖对应配置。成熟公司排除表和公司画像资料表都保留在版本控制中，便于审阅事实、别名和证据来源的变化。正文读取最多并发八个请求，单个请求默认超时八秒，页面不可读时自动退回标题和 RSS 摘要。

## 公司画像资料表

资料表解决两个不同问题：先把 `TypeSafe`、`TypeSafe AI`、`Jev` 等别名归一为真实公司，再用公司官网、官方融资公告或可靠媒体补齐明确事实。每条画像至少需要：

- `name`：统一后的公司名；
- `aliases` 或 `match_patterns`：用于识别别名和标题中未直接出现公司名的报道；
- 一个或多个经过核验的字段；
- 至少一个带 `https://` URL 的 `sources` 证据。

画像会覆盖已知错误的业务描述，其他列表字段与报道证据合并；画像融资阶段与报道阶段取更晚者。`exclude_reason` 可用于已明确不属于早期 BD、但新闻没有披露标准轮次的公司。该资料表不是无来源知识库，不能写入推测、搜索摘要猜测或无法回读的事实。

## 输出字段

- 公司：报道明确指向的创业公司；无法确认时不猜测。
- 业务与方向：把“主要业务”和“所属方向”合并为一个展示条目。两项都有时使用“主要业务（所属方向）”，只有一项时直接展示已有证据；底层仍分别保存。主要业务优先使用标题和摘要，所属方向仅根据业务描述映射，不根据公司名称猜测。
- 融资阶段：种子、天使、A/B/C 等明确轮次；“新一轮”“两轮”但未披露轮次时保持未知。
- 所在地：把“总部所在地”和“核心团队所在地”合并为一个展示条目。同地时合并标记为“总部及核心团队”，异地时在同一行分别标注；只有一项时显示已有地点及其类型。地点仍只提取“总部位于”“团队位于”“headquartered in”等明确陈述，不从媒体 dateline、学校或创始人籍贯推断。
- 级别：沿用 Jev 的 A/B 级判断。
- 触发事件：融资、团队或业务变化的原始标题。
- 资方：只识别标题和 RSS 摘要中明确出现的机构。
- 团队：从标题、摘要及与该公司同句出现的正文证据中提取。
- 来源：合并后的公开报道链接。

## 验证

```bash
uv run python -m unittest discover -s tests -p 'test_*.py'
```

核心回归测试覆盖中英文公司名、投资机构、团队证据、未知字段、同公司合并、飞书渲染以及旧 `<font>` 标签清理。

## 成熟度门槛与审计

- C 轮及以后、Pre-IPO 和已上市公司不会进入飞书批次。
- `mature_company_exclusions` 用于处理新闻未披露轮次、但已经明确不属于早期 BD 的公司。
- 每家被排除的公司和原因都会写入 GitHub Actions 日志，例如 `[公司情报] 排除 Anthropic：已知成熟公司，不属于当前早期 BD 阶段`。
- 若所有候选都被排除，outbox 会生成空 `batches`，不会退回旧新闻列表绕过门槛。
